# i18n status: Applies — seam merged, qualified review outstanding

CEQA Preflight produces natural-language console and HTML reports for planners,
clerks, consultants, and reviewers working in a California civic process. That
surface does not qualify for the portfolio standard's single-developer-operator
exemption, so internationalization applies.

The gettext seam now exists. `ceqa_preflight.i18n` selects a catalog, every
report surface renders through it, and `make verify` enforces the four checks
this document has always asked for. What remains is the part that needs a
person rather than a commit: a qualified Spanish-language CEQA reviewer.

## Current boundary

What locale selection may change:

- console messages, HTML report prose, checklist prose, finding summaries,
  remediation guidance, skipped-check explanations, and user-visible errors.

What locale selection must never change, and what `tests/test_i18n.py` pins:

- command names, option names, and the flag strings quoted inside messages
  (`--include-experimental`, `--rules`, `--exclude-rules`);
- machine-readable JSON field names, `report_schema_version`, `filing_type`;
- rule identifiers and rule versions;
- finding status values (`pass`, `warning`, `failure`, `manual`) and skip
  reasons;
- source citations: title, URL, and section, which name published documents;
- the process exit code, which is how a pipeline routes.

Two further rules stand above all of the above:

- Filing-package text is user data. It must never be sent to a translation
  service or added to a message catalog. Nothing in `babel.cfg`'s extraction
  map can reach it: only `src/ceqa_preflight/` is scanned.
- No language may imply that an advisory finding is a legal determination.

## What is deliberately not translated, and why

- **Rule catalog titles** (`rulepacks/*.yaml`). They are versioned catalog data
  with a change-control discipline of their own; moving them into a message
  catalog would let a rule's identity drift from its recorded version.
- **Source citation titles.** They name published documents. A translated
  citation would no longer be the citation.
- **Pilot `reasons` strings** (`ceqa_preflight.pilot`). They are the controlled
  vocabulary of a recorded evidence artifact that is mirrored verbatim into
  `pilot summarize --format json`. An evidence record whose wording depends on
  a display flag is not a stable record. The console labels around them are
  translated; the recorded reasons are not.
- **CLI help text.** Typer binds help strings when the module is imported,
  before any command line has been parsed. Translating it correctly needs a
  lazy-help mechanism, not a `_()` call, and a per-process cached translation
  would be wrong in exactly the way this seam exists to prevent. Tracked as
  remaining work below.
- **The opt-in `ai` command prose** (`ceqa_preflight.ai.messages`). Those
  strings are already centralized in one module so the seam can wrap them in a
  single pass. They are held back deliberately: the module contains the
  legal-sufficiency refusal, whose Spanish wording is assigned to the qualified
  reviewer in [#49](https://github.com/ChelseaKR/ceqa-preflight/issues/49).
  Drafting an unreviewed Spanish refusal would put the single riskiest sentence
  in the tool into a catalog ahead of the review that governs it.

## Using it

Locale selection is explicit at the command-line boundary:

```sh
ceqa-preflight --locale es check ./my-package --filing-type NOE
```

Nothing is inferred. `LANG`, `LC_ALL`, `LANGUAGE`, and `LC_MESSAGES` are not
read; neither is any network response, IP address, or document content. A run
that was not told which language to use is an English run, so a report is
reproducible from its command line alone.

Three outcomes, all of them stated rather than silent:

| Requested | Result |
|---|---|
| omitted, `en`, `es`, `es-MX`, `ES` | that catalog is used |
| `fr`, `pt-BR`, any well-formed tag with no catalog | English, plus a note on stderr naming the tag that could not be met |
| `espanol!`, `es-`, `english` | usage error, exit 2; a typo is reported, not silently downgraded |

Selecting a non-English catalog also prints, on stderr, that the translation
has not passed qualified review and that English is authoritative.

The first public tagged release is blocked until:

1. ~~the gettext entry point and extraction configuration are merged~~ —
   **done.** `ceqa_preflight/i18n.py`, `babel.cfg`, and
   `src/ceqa_preflight/locales/`.
2. ~~English and Spanish catalogs compile with complete key and placeholder
   parity~~ — **done.** 158 messages, both catalogs at 100%, enforced by
   `make i18n`.
3. a qualified Spanish-language reviewer approves CEQA terminology and the
   advisory/non-legal framing — **open.** The shipped `es` catalog is a
   maintainer draft and says so in its header, on every non-English run, and
   in the README. Tracked with
   [#49](https://github.com/ChelseaKR/ceqa-preflight/issues/49).
4. ~~console and HTML report tests cover English, Spanish, and deterministic
   fallback~~ — **done.** `tests/test_i18n.py`.
5. the central applicability registry marks CEQA Preflight as I18N `applies` —
   **open**, and outside this repository.

## What `make verify` enforces

`make i18n` runs inside `make verify`, which is what CI runs. It is one Python
program, `scripts/check_i18n.py`. It regenerates the extraction template and
each compiled catalog in memory and compares, so the gate writes nothing and can
never quietly repair the drift it exists to report. Doing that in Python rather
than through `pybabel` and `cmp` also keeps it working on every platform: an
earlier version shelled out through a POSIX scratch path, which the Windows CI
job could not write to.

| Check | Fails when |
|---|---|
| Extraction freshness | a string was wrapped in `_()` but never extracted, so it could never be translated, or the template still carries a message source no longer wraps |
| Catalog compilation | a `.po` was edited and its `.mo` was not rebuilt |
| POT/EN/ES key parity | a message is missing from a catalog, or a catalog carries one the template does not |
| Placeholder parity | a translation drops, invents, or repeats a `{placeholder}`, which would blank a value or raise at format time |
| BCP 47 validity | a locale directory is not a valid language tag, or a catalog's `Language:` header disagrees with its directory |
| No fuzzy or empty | a message is untranslated or marked fuzzy |
| English identity | an English `msgstr` drifts from its `msgid`, which would change English prose invisibly |
| Compiled agrees with source | a `.mo` says something its `.po` does not, the exact shape of a silent fallback; checked both message by message and byte for byte |
| Locale ships at all | a supported locale stops shipping a catalog, rather than everyone quietly reverting to English |

Every one of those rows has a test in `tests/test_i18n.py` that breaks that one
property against a throwaway copy of the catalogs and asserts the gate goes red,
plus a control case that asserts it stays green on an unmodified copy. A gate
that cannot fail is not a gate.

Byte comparison of the compiled catalogs is only sound because every `.po` pins
a complete header including `POT-Creation-Date`. Babel invents that field from
the wall clock when a catalog omits it, which would make the gate fail on a
clean tree. Do not delete those header lines.


## Adding or changing a string

1. Wrap it: `from ceqa_preflight.i18n import gettext as _`, then `_("…")`.
   Use `{name}` placeholders and `.format()`; keep format specs such as `:.0%`
   outside the message, because a translator supplies words, never a Python
   format spec.
2. Do not build a message by concatenating fragments, and do not put a
   translated string in a module-level constant: a constant is evaluated at
   import, which freezes whichever language happened to be active first. Use a
   small function instead, as `reporting.all_checks_ran()` does.
3. `make i18n-update` to re-extract and recompile.
4. `pybabel update -i src/ceqa_preflight/locales/messages.pot -d src/ceqa_preflight/locales --omit-header`
   to carry a new message into each catalog, then translate it and clear the
   fuzzy flag. `make i18n` fails while any message is fuzzy or empty.
5. `make i18n` to check, `make verify` before pushing.
